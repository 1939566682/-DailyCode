# beacon-cloud 项目整体分析

> 分析日期：2026-06-29  
> 分析范围：全部 10 个 Maven 子模块 + 基础设施配置 + 前端管理后台

---

## 一、项目定位

**beacon-cloud 是一个基于 Spring Cloud 微服务架构的分布式短信平台（SMS Gateway Platform）**，提供从 API 接入、校验、策略路由到运营商通道下发的完整短信发送链路，并配套管理后台、数据同步、搜索和监控能力。

核心业务场景：验证码短信、通知短信、营销短信。

## 三、模块全景（10 个 Maven 子模块）

### 3.1 核心短信链路（4 个模块）

| 模块 | 端口 | 职责 | 关键类 |
|------|------|------|--------|
| **beacon-api** | 10001 | API 接入网关，接收短信发送请求，执行前置校验链（apikey→ip→sign→template→mobile→fee），通过后投递到 RabbitMQ | `SmsController`, `CheckFilterContext`, `CheckFilter` 接口及 6 个实现 |
| **beacon-strategy** | 18883 | 策略处理中心，消费 MQ 消息执行二次策略校验（号段补全→敏感词DFA→黑名单→频次限制→计费→通道路由），通过后投递到 push 队列 | `PreSendListener`, `StrategyFilterContext`, `StrategyFilter` 接口及 9+ 个实现 |
| **beacon-push** | 18885 | 推送模块，消费策略模块产出的消息，按通道路由到具体的短信网关 | `PushStarterApp`, `RabbitMQConfig` |
| **beacon-SmsGateway** | 18886 | 短信网关，基于 Netty 实现 CMPP 协议客户端，连接运营商短信中心（SMSC）完成实际短信下发 | `NettyClient`, `CMPPDecoder`, `CMPPEncoder`, `CmppSubmit` 等协议实体 |

### 3.2 数据与缓存（3 个模块）

| 模块 | 端口 | 职责 |
|------|------|------|
| **beacon-cache** | 18882 | Redis 缓存服务封装，提供 hmset/set/pipeline 等 REST API 供其他模块调用 |
| **beacon-synchronization** | - | 数据同步模块，负责 MySQL ↔ Redis 数据同步，管理 Client/Channel/Blacklist/MobileArea/DirtyWord 等实体和 Mapper |
| **beacon-search** | 18884 | Elasticsearch 搜索服务，提供短信发送记录检索和报表能力 |

### 3.3 运维与管理（2 个模块）

| 模块 | 端口 | 职责 |
|------|------|------|
| **beacon-monitor** | 18887 | 监控告警模块，集成 XXL-Job 定时任务 + 邮件告警（QQ邮箱 SMTP） |
| **beacon-webmaster** | - | 管理后台，Spring Boot + Shiro + MyBatis + 原生 HTML/JS 前端，管理客户、通道、黑名单、敏感词、计费、报表等 |

### 3.4 公共模块（1 个模块）

| 模块 | 职责 |
|------|------|
| **beacon-common** | 公共常量（ApiConstant/SmsConstant/CacheConstant）、枚举（MobileOperatorEnum）、异常（StrategyException/ApiIllegalException/SearchException）、工具类（SnowFlakeUtil/JsonUtil/OperatorUtil） |

## 四、核心业务流程

### 短信发送全链路

```
客户端请求
  │ POST /sms/single_send (apikey, mobile, text, uid, state)
  ▼
[beacon-api :10001]
  │ 1. 参数校验 (Spring Validation)
  │ 2. 获取真实 IP (多级代理头解析)
  │ 3. 构建 StandardSubmit 对象
  │ 4. 执行前置校验链 (CheckFilterContext)
  │    ├─ ApiKeyCheckFilter  (apikey 合法性)
  │    ├─ IP 校验
  │    ├─ SignCheckFilter    (签名校验)
  │    ├─ TemplateCheckFilter(模板校验)
  │    ├─ MoblieCheckFilter  (手机号格式)
  │    └─ FeeCheckFilter     (计费/余额预检)
  │ 5. 雪花算法生成 sequenceId
  │ 6. 投递到 RabbitMQ (SMS_PRE_SEND)
  ▼
[RabbitMQ: SMS_PRE_SEND]
  ▼
[beacon-strategy :18883]
  │ PreSendListener 消费 (手动 ACK)
  │ StrategyFilterContext 执行策略链
  │ (校验顺序由 Redis 中 clientFilters 动态配置)
  │    ├─ PhaseStrategyFilter        (号段补全：前7位查归属地+运营商)
  │    ├─ DirtyWordDFAStrategyFilter (敏感词DFA算法)
  │    ├─ BlackClientStrategyFilter  (客户级黑名单)
  │    ├─ BlackGlobalStrategyFilter  (全局黑名单)
  │    ├─ LimitOneMinuteStrategyFilter(1分钟频次限制)
  │    ├─ LimitOneHourStrategyFilter  (1小时频次限制)
  │    ├─ FeeStrategyFilter           (计费扣费)
  │    └─ TransferStrategyFilter      (通道路由选择)
  │ 通过 → ACK / 失败 → Reject
  ▼
[RabbitMQ: push 队列]
  ▼
[beacon-push :18885]
  │ 消费消息，按路由选择具体通道
  ▼
[RabbitMQ: sms_gateway_topic_1]
  ▼
[beacon-SmsGateway :18886]
  │ NettyClient 连接运营商 SMSC
  │ CMPP 协议：Connect → Submit → Deliver → ActiveTest
  │ 编解码：CMPPEncoder / CMPPDecoder
  ▼
[运营商短信中心 (中国移动/联通/电信)]
  │
  ▼
用户手机收到短信
```

### 设计模式亮点

1. **策略模式 + 责任链**：API 模块和 Strategy 模块均使用 `XxxFilterContext` + `Map<String, Filter>` 注入实现动态校验链，校验顺序可通过 Nacos/Redis 动态配置
2. **事件驱动**：模块间通过 RabbitMQ 解耦，支持 confirm + return 机制保证消息可靠投递
3. **雪花算法**：全局唯一 ID 生成（SnowFlakeUtil）
4. **DFA 算法**：敏感词过滤使用确定有限自动机实现高效匹配
5. **CMPP 协议**：Netty 自定义编解码器实现运营商短信协议

## 八、项目状态与观察

### 已完成
- 核心短信发送链路（API → Strategy → Push → Gateway）基本完整
- 前置校验链 6 个过滤器实现
- 策略校验链 9+ 个过滤器实现
- CMPP 协议 Netty 客户端（编解码、心跳、重连）
- 管理后台前端页面 + 后端 CRUD（含代码生成器）
- 数据同步模块（MySQL ↔ Redis）
- Nacos 配置中心集成

### 待完善（代码中的 TODO 标记）
1. `PhaseStrategyFilter`：第三方查到号段信息后同步到 MySQL 和 Redis 的逻辑未完成
2. `PhaseStrategyFilter`：查不到号段时通知（发送邮件）未实现
3. `DirtyWordDFAStrategyFilter`：检测到敏感词后的处理逻辑未完成（仅日志记录）
4. `generate_webmaster_code_v2.py`：webmaster 后端代码为脚本生成，部分可能需要人工校对

### 潜在风险
1. **敏感信息暴露**：Nacos 配置中包含明文密码（Redis 密码、ES 密码、邮箱授权码、MySQL root 密码），生产环境需加密
2. **测试覆盖**：synchronization 模块有 Mapper 测试，但核心链路（API/Strategy/Push/Gateway）缺少单元测试
3. **Java 8 + Spring Boot 2.3**：版本较旧，存在已知安全漏洞，建议升级
4. **异常处理**：策略模块 `StrategyException` 被 Reject 后消息直接丢弃（`basicReject(tag, false)` 不重新入队），可能导致消息丢失

## 十、总结

beacon-cloud 是一个功能完整的**分布式短信平台**，架构设计合理：

- **微服务拆分清晰**：按职责拆为接入、策略、推送、网关、缓存、同步、搜索、监控、管理 9 个业务模块 + 1 个公共模块
- **异步解耦**：核心链路通过 RabbitMQ 串联，各模块可独立扩缩容
- **动态配置**：Nacos + `@RefreshScope` 实现校验链顺序等配置热更新
- **协议层**：Netty 自实现 CMPP 编解码，具备运营商级短信下发能力
- **管理闭环**：webmaster 后台覆盖客户/通道/黑名单/敏感词/计费/报表全管理链路

主要改进方向：安全加固（密码加密）、版本升级（Spring Boot 3 + JDK 17）、测试补全、消息可靠性保障（死信队列）。
