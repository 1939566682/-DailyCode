# 前后端接口路径全面审计报告

## 📌 TL;DR
发现并修复了三类问题：(1) 响应格式不匹配导致接口返回404；(2) 缺失的MenuController；(3) Shiro认证拦截未登录请求。

---

## ✅ 已修复的问题

### 1. 响应格式不匹配（核心404原因）

**问题**：前端JS期望特定的命名字段（如 `r.acount`、`r.sites`），但后端返回 `{code:0, msg:"success", data:<object>}`，数据在通用的 `data` 字段中，前端无法读取。

**修复方案**：
- 新增 `R.okNamed(String key, Object value)` 方法到 `R.java`
- 返回格式: `{code:0, msg:"success", <key>: <value>}`
- 21个接口已修改（15个info + 6个all）

**前端JS同步修复**：
| 文件 | 原代码 | 修复后 |
|------|--------|--------|
| index.js 第54行 | `vm.user = r.data` | `vm.user = r.user` |
| search.js 第83行 | `vm.sites = r.data` | `vm.sites = r.sites` |
| menu.js 第58行 | `field: 'orderNum'` | `field: 'sort'` |

**EchartsController pie 接口**：
- 前端 smspie.js 期望 `r.legendData` + `r.seriesData`
- 后端改为返回 `{code:0, msg:"success", legendData:[...], seriesData:[...]}`

### 2. 新增 MenuController（6个接口）

menu.js 之前没有对应后端Controller。已创建：

| 接口路径 | 方法 | 响应格式 |
|---------|------|---------|
| `/sys/menu/list` | GET | R.ok(total, rows) |
| `/sys/menu/del` | POST | R.ok() |
| `/sys/menu/info/{id}` | GET | R.okNamed("menu", ...) |
| `/sys/menu/save` | POST | R.ok() |
| `/sys/menu/update` | POST | R.ok() |
| `/sys/menu/select` | GET | R.okNamed("menuList", ...) |

同时扩展了 MenuService 和 MenuServiceImpl，新增 5个方法。

### 3. Shiro 认证拦截

**关键发现**：所有 `/sys/*` 接口被 Shiro `authc` filter 拦截，未登录访问会302重定向到 `/login.html`，AJAX请求表现为404。

**测试API前必须先登录！**

## ⚠️ 仍缺失的Controller（需额外Service/Mapper/Entity/数据库表）

| 前端JS | 接口前缀 | 缺失原因 | 需要什么 |
|--------|---------|---------|---------|
| role.js | `/system/role/*` | 无Controller，路径前缀不同 | sms_role_menu/sms_user_role关联表的Entity/Mapper/Service |
| smstemp.js | `/sys/smstemp/*` | 无Entity/Mapper/Service | sms_template表 |
| smssend.js | `/sys/sms/save/update` | 无对应Service | 短信发送功能 |

**role.js 特殊情况**：
- 路径前缀 `/system/role/`（不是 `/sys/role/`）
- 响应格式用 `r.status`（不是 `r.code`）
- 需6个接口：list/delete/info/add/update/menu_tree/role_menu/assign_menu
