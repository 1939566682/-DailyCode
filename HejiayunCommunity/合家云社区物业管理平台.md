# 合家云社区物业管理平台

> 时长：约5-10分钟 | 语速适中即可

---

## 【开场白】

大家好，我今天给大家讲的项目叫"合家云社区物业管理平台"。

简单来说，这就是一套物业公司用来管理小区的系统。物业的工作人员登录之后，可以新增小区、修改小区信息、删除小区、按条件搜索，还能一键导出 Excel 报表。同时系统还有完整的用户管理和权限控制——什么人能干什么事，都有严格的限制。

整个项目是前后端分离的架构。后端用的是 Spring Boot 2，前端是 Vue 2 加 Element UI 组件库，数据库用的 MySQL 8，再加上 Redis 做缓存。

好，下面我从项目结构、核心功能到演示流程，给大家完整讲一遍。

---

## 一、项目结构

核心的有两个：一个是 `hjy-community`，这是后端的 Spring Boot 工程，整个物业系统的主要代码都在这里；另一个是 `hejiayun_ui`，这是前端的管理后台页面。

另外还有四个练习模块。分别是 `springsecurity_example` 和 `springsecurity_example2`，是我学习 Spring Security 权限框架时做的两个小项目，一个练表单登录加验证码，一个练 JWT 令牌加注解权限。还有 `easypoi_boot` 是练 Excel 导出的，`easy_code` 是一个代码生成器。

前后端之间怎么通信的呢？前端运行在 80 端口，后端运行在 8080 端口。前端的每个请求路径前面都会加一个 `/hejiayun` 前缀，然后通过代理配置转发给后端。这样做的好处是解决了跨域问题——因为前端和后端端口不一样，浏览器默认是不允许跨端口通信的，加上这个代理就绕过了浏览器的限制。

---

## 二、技术栈

技术栈方面，我分后端和前端来说。

后端用的是 Spring Boot 2.7.8，这是目前企业级开发的主流框架。权限控制用的 Spring Security，数据库操作用的是 MyBatis-Plus，也就是 MyBatis 的增强版，可以不用写 SQL 就能完成大部分增删改查。数据库是 MySQL 8.0，配了 Druid 连接池管理数据库连接。缓存用的 Redis，客户端是 Jedis。用户登录后生成的令牌是 JWT 格式，不需要在服务端存会话信息。分页查询用的是 PageHelper，Excel 导出用的是 EasyPOI。

前端是标准的企业级后台管理模板。Vue 2.6.10 作为框架，Element UI 2.14 提供界面组件，Vue Router 管理页面路由，Vuex 做全局状态管理，Axios 做 HTTP 请求。首页仪表盘用了 ECharts 图表库展示统计数据，用户令牌存在 cookie 里，用的是 js-cookie 这个库。

---

## 三、后端详解

后端的包结构分成了五层，我按从底层到上层的顺序讲。

第一层是 `common` 公共层。这里面放的是所有模块共享的东西。比如统一的响应格式，所有接口返回的数据都是 `{code, msg, data, success}` 这样的结构，前端拿到之后统一处理。还有实体类的基类，自动填充创建时间和更新时间。还有全局异常处理器，把所有的 Java 报错统一拦截下来，返回给前端友好的提示信息，不会把堆栈信息暴露出去。

第二层是 `framework` 框架层。这里放的是安全配置。核心有两个东西：一个是 SecurityConfig，配置哪些接口是公开的，比如登录接口和获取验证码的接口不需要登录就能访问，其他接口都需要登录。另一个是 JWT 过滤器，每一个请求进来先经过这个过滤器，解析 token，从 Redis 里取出当前用户的信息，然后放到 Spring Security 的安全上下文中。

第三层是 `system` 系统管理层。这里面向系统管理员，管理用户、角色、菜单、部门、字典这些基础数据。

第四层是 `community` 业务层。这是物业业务的核心，主要是小区管理。小区这个实体包含了小区名称、编码、所在省份市区划、详细地址、经纬度、所属物业公司这些字段。

第五层是 `web` 控制层。所有的 API 接口都在这一层，一共 26 个接口，后面我会具体讲。

---

## 四、API 接口

26 个接口分成四大类。

第一类是认证接口，有 5 个。包括获取验证码图片、登录、登出、获取当前用户信息和权限、以及获取当前用户的菜单路由。

第二类是小区管理接口，有 7 个。包括分页查询小区列表、新增小区、查看小区详情、修改小区信息、批量删除小区、下拉列表查询，以及导出小区 Excel 报表。

第三类是系统管理接口，有 14 个。包括部门列表、地区树形数据、字典数据的增删改查、字典类型的增删改查和清空缓存。

这些接口大多需要登录才能访问，而且有权限控制。比如新增小区需要拥有 `system:community:add` 这个权限，删除需要 `system:community:remove` 权限，没有权限的话即使登录了也调用不了。

---

## 五、权限控制详解

这是这个项目的一个核心亮点——前端和后端做了双重权限控制。

先说后端。在每个接口的方法上加上 `@PreAuthorize` 注解，比如新增小区的方法上写 `@PreAuthorize("hasPermission('system:community:add')")`。用户登录的时候，系统会查这个用户有哪些角色，每个角色有哪些菜单权限，然后把权限列表存到 Redis 里。之后每次请求过来，JWT 过滤器从 Redis 取出这个用户的权限，Spring Security 自动比对当前接口需要的权限和用户实际拥有的权限，不匹配就直接返回 403 无权访问。

再说前端。前端页面上，每个按钮都用 `v-hasPermi` 指令控制显示，比如说"新增"按钮上写 `v-hasPermi="['system:community:add']"`。如果当前登录的用户没有这个权限，这个按钮根本就不会渲染出来，用户连点击的机会都没有。

另外页面路由也是动态的。用户登录成功后，前端会调用后端的 `/getRouters` 接口，获取当前用户可以访问的菜单列表，然后动态生成路由表。没有权限的页面不会出现在侧边栏菜单里，即使用户直接在地址栏输入 URL，也会被跳转到无权限提示页面。

## 六、前后端对接流程——以新增小区为例

我以新增小区这个操作为例，给大家完整讲一遍前后端是怎么协作的。

用户在浏览器左侧菜单点击"小区管理"，进入小区列表页面。页面上有一个"新增"按钮，点一下弹出一个表单对话框，里面要填小区名称、编码、省份、城市、区县、详细地址、经纬度这些信息。填完之后点击"确定"按钮。

这时候前端触发一个事件，调用 API 层封装好的 `addCommunity` 方法。这个方法用 Axios 发送一个 POST 请求，路径是 `/hejiayun/community`。在请求发出之前，Axios 的请求拦截器会自动从 cookie 里取出登录令牌，放到请求头的 `Authorization` 字段里，格式是 `Bearer 令牌字符串`。

请求到达前端的代理服务器。代理配置在 `vue.config.js` 里，只要路径以 `/hejiayun` 开头，就自动转发到后端的 `localhost:8080`，同时把 `/hejiayun` 前缀去掉。所以后端的 Controller 接收到的实际路径是 `/community`。

后端的 Controller 先检查用户有没有新增小区的权限。有权限的话调用 Service 层，Service 层先生成一个小区编码，编码规则是 `COMMUNITY_` 加时间戳。然后调用 Mapper 把数据插入数据库，最后返回成功响应。

前端收到后端的成功响应后，弹出一个成功提示，然后自动刷新小区列表，用户就能在表格里看到刚才新增的那条记录了。

整个流程从用户点击按钮到看到结果，也就一两秒钟的时间。

## 七、演示流程

接下来我给大家演示一下这个系统的实际运行效果。

第一步，打开浏览器，访问 `http://localhost`，会看到登录页面。页面上有合家云的标志，需要输入用户名、密码和验证码。验证码点击图片可以刷新。

第二步，输入管理员账号 `admin`，密码 `admin123`，然后输入验证码，点击登录。登录成功后会自动跳转到首页仪表盘。

第三步，首页上有四个统计数字面板，数字会滚动显示。下面有 ECharts 生成的图表，包括柱状图、折线图、饼图和雷达图，展示物业运营的各类统计数据。

第四步，点击左侧菜单的"小区管理"，进入小区列表页面。页面上方有搜索栏，可以按小区名称或编码进行模糊搜索。下方表格显示所有小区的数据，包括序号、名称、编码、地址、创建时间这些信息。

第五步，点击"新增"按钮，弹出一个表单，填写小区信息后保存，可以看到表格里多了一条数据。

第六步，勾选一条或多条数据，点击"导出"按钮，浏览器会下载一个 Excel 文件，里面是勾选的小区数据。

第七步，点击左侧菜单的"系统管理"下面的"用户管理"或"角色管理"，可以看到用户和角色的配置页面。在这里可以给用户分配角色，给角色分配菜单权限。

大家可以用 F12 打开开发者工具，切换到 Network 面板，可以看到每一个请求的详细信息——请求的路径、请求头的 token、服务器返回的 JSON 数据，非常直观。

## 【结束语】

最后做个总结。

合家云社区物业管理平台是一个完整的前后端分离项目。后端用 Spring Boot + Spring Security + MyBatis-Plus 实现了标准的 RBAC 权限管理系统，加上小区业务管理。前端用 Vue 2 + Element UI 实现了完整的后台管理界面，包含登录、仪表盘、小区管理、系统管理、系统监控等二十多个页面。

旁边的四个练习模块记录了我从 Spring Security 入门到最终整合实战的完整学习路径：先从表单登录开始，然后学 JWT 鉴权，再做 EasyPOI 的 Excel 导出练习，最后用代码生成器来辅助开发。

以上就是我今天的讲解，谢谢大家！

## 【附录：可能被提问的问题】

如果老师提问，以下是几个常见问题的回答。

**问：项目启动需要什么环境？**
答：需要 JDK 8 或 11、MySQL 8.0、Redis、Node.js 14 到 16 版本。先启动 MySQL 和 Redis，然后运行后端的 `mvn spring-boot:run`，再运行前端的 `npm run dev`，浏览器打开 `http://localhost` 就能看到登录页。

**问：前后端分离的好处是什么？**
答：第一是开发分离，前端和后端可以并行开发互不干扰。第二是部署灵活，前端可以部署在 Nginx 上，后端可以独立扩展。第三是维护方便，修改前端不影响后端，反过来也一样。

**问：你遇到的比较难的问题是什么？**
答：学习中比较难的是理解 Spring Security 的过滤器链和 JWT 的认证流程。后来通过先做两个练习模块——先用表单登录理解认证的基本流程，再加入 JWT 理解无状态鉴权——逐步掌握了。

**问：如果要扩展功能，会怎么扩展？**
答：如果继续开发，可以从三个方面扩展。业务上增加楼宇管理、房屋管理、业主管理、报修工单、访客登记这些物业核心功能。系统上可以加操作日志记录和定时任务。技术上升级到 Vue 3 和微服务架构。
