## 三、数据流转

```
[客户端] HTTP POST /sms/single_send
    ↓
[beacon-api]
  1. 参数校验 (Bean Validation)
  2. IP 获取
  3. 校验链: apikey → ip → sign → template → mobile → fee
  4. 雪花算法生成 sequenceId
  5. 发送 MQ: sms_pre_send_topic
    ↓
[beacon-strategy] 消费 MQ
  1. 策略链: dirtyword → blackClient → blackGlobal → limitOneMinute → limitOneHour → fee → route
  2. fee 扣费 (Redis DECR)
  3. route 选择通道 → 动态创建队列 → 转发 MQ
  4. 失败时: 写 ES + 推送状态报告
    ↓
[beacon-SmsGateway] 消费 MQ: sms_gateway_topic_{clientId}
  1. Netty 客户端通过 CMPP 2.0 协议发送到运营商
  2. 接收运营商响应 (submit resp + deliver 状态报告)
  3. 写 ES 日志
  4. 推送状态报告
    ↓
[beacon-search] 消费 MQ
  1. SMS_WRITE_LOG → 写入 ES
  2. 死信队列延迟 10s → 更新 ES 报告状态
    ↓
[beacon-push] 消费 MQ
  1. 通过 REST 回调推送状态报告给客户端
  2. 失败重试: 15s/30s/60s/5min 指数退避
```
